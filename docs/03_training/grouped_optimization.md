# 分组验证与最终训练

## 为什么改划分

v0.1 在随机图片验证上达到 98.81%，官方测试仅 80.91%。同一渲染序列的相似姿态可能跨越训练和验证。v0.2 用文件名前缀划分完整序列：每类七个序列中的五个训练、两个验证，得到 1,800 / 720 张开发样本。官方 372 张测试成员不变。

前缀只是可审计的序列线索，不是经过确认的人员身份。真实部署时需要按人、采集会话和场景分组。原 `manifest.json` 不变，新划分保存为 `manifest_grouped.json`；完全重复检查与序列互斥检查分别解决不同问题。

## 有限候选

先保存 `plan.json` 再开始训练。三个候选分别为 width=8 的基础配置（25 轮）、width=8 + affine（60 轮）、width=16 + affine（60 轮）。后两个候选增加旋转、平移、缩放、亮度和对比度覆盖。

组合策略与基础配置同时改变了增强和训练预算，因此本实验不能单独量化某一种增强的贡献。宽度比较使用同样的策略与轮数。候选只按验证 accuracy、验证 loss、参数量依次排序，不根据官方测试挑选。

```bat
python scripts/optimize.py
python scripts/evaluate_selected.py
python scripts/refit_selected.py
```

这些命令使用 `artifacts/v0.2-grouped-study`，已有结果时会拒绝覆盖。需要新实验时可在 Notebook 03 将 `RUN_TRAINING=True`，自动创建时间戳目录。Notebook 默认读取仓库内真实 JSON 记录，便于先理解实验再消耗算力。

## 最终训练与开发验证的区别

开发候选的最佳轮次为 36，原学习率调度周期是 60。最终训练把官方训练池中的 2,520 张图全部用于训练，重新初始化模型，训练固定 36 轮，保留 60 轮的学习率日程，不做新的早停或选模。

不把旧开发验证集继续当作独立验证，也不报告最终模型的所谓验证准确率。保存文件为 `best.pt` 是为了兼容现有工具；其元数据明确记录它是固定协议下的最后一轮。最终训练协议与指标独立归档。

本次先评估了开发候选、随后完成最终训练并再评估；此前 v0.1 也观察过官方测试。因此这些结果属于回顾性公开基准。原始测试图从未进入训练/校准，最终配置只来自开发选模，但不能把该测试冒充新的盲测验收。未来相机验收必须另留独立数据。

## 仍需解决的边界

这是单手、固定 ROI、三类别闭集分类。softmax 无法可靠识别空场景与未知手势。先补充 background/other 与实拍，再定义各类别召回率、误触发率和时序稳定性指标。下一阶段的 INT8 量化应固定本轮最终权重，校准只使用训练池代表性样本。

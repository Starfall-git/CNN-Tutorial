# 阶段 5.4：独立静态硬件工程预检查

2026-10-04，读取独立 FPGA 副本、厂商本地 DDR3 示例及 `refs/Board/Ti60_F225_Core_V1.4.pdf` 第 5 页。此步骤是差异核对，尚未生成或下载新的硬件。

## 可以对应上的连接

两份 `.peri.xml` 的 24 MHz 输入都在 `GPIOL_11`，25 MHz 输入都在 `GPIOR_29`，电平均为 3.3 V。UART RX 都在 `GPIOT_N_16`、TX 都在 `GPIOT_P_16`，电平均为 1.8 V；信号名称分别使用视频工程和 Sapphire 命名。

逐项查看的 DDR 地址、bank、DQ、DM 和控制 GPIO 位置相符，但旧示例与现有工程的控制器、时钟和外围封装不同。引脚对应不能替代完整接口/时序检查，尤其是差分时钟、DQS、校准及复位。

## 不能直接沿用的设置

| 项目 | 视频正式工程 | 本地 DDR3 TinyML 示例 | 接入动作 |
|---|---|---|---|
| Efinity | 2026.1.132.3.9 | 2025.1.110.1.5 | 在独立副本迁移、重新生成需要的 IP |
| 速度等级 | C4 | I3 | 静态工程按实际器件约束重做时序 |
| 系统时钟 | 视频系统约 96 MHz | Sapphire 配置 CPU 300 MHz、外设 100 MHz | 不把 300 MHz 视为本板已通过值 |
| DDR 控制器 | `ip/DdrCtrl/settings.json` | `src/ddr3_controller/` | 不混接两种 PHY/时序参数 |
| 行地址配置 | `row=16` | `ROW_WIDTH=14` | 核对实际颗粒与控制器寻址语义，不由参数直接推算可用容量 |
| DDR 数据/AXI | DQ 16、AXI 128 位 | DQ 16、AXI 128 位 | 仍需核对 ID、burst、地址与桥接 |
| 固件布局 | 低 48 MiB 为视频帧槽 | 当前 linker 入口 0x1000、区域 128 MiB | 静态验证独立运行；集成时重新规划 |

提供的核心板原理图第 5 页 U2 标注 `MT41J128M16JT-125`。按型号标注的 128M×16 位组织换算为 256 MiB；这属于**文档所示器件**，并非已读取实板料号或验证可访问容量。原理图还画出 A14/A15 等引脚，不能仅按画出的总线线数断言地址几何。当前不改正式视频控制器参数，也不把旧 BSP 声明范围当作实测容量。

## 上板前的交付条件

1. 创建单独的静态硬件工程，保留现有视频工程可恢复版本；匹配 C4、实际晶振、DDR3 和 UART/JTAG。
2. 从该硬件工程生成 BSP，与固件的时钟、外设地址、ISA 和 linker 一起保存；重新编译固件。
3. 先验证 UART、DDR 初始化和小范围内存读写，再运行冻结模型的三组 golden 自检。
4. 保存完整串口日志、实际 CPU Hz、arena、输出字节与周期，再启用匹配的 2026 TinyML 加速路径进行同输入比较。

本轮 Windows 的 `Win32_SerialPort` 以及按 FTDI/JTAG/USB Serial/CH340 名称筛选的 PnP 查询未返回设备。它只说明本次查询没有发现对应项，不能区分未连接、驱动未安装或设备使用其他名称。已向用户询问供电/JTAG/UART 连接状态；没有打开串口、复位、下载或烧写。

# 简单 GitHub 工作流

目标仓库：`Starfall-git/CNN-Tutorial`，Private。Git 提交使用此仓库的本地身份配置，不修改全局 Git 身份。

1. `main` 保存基线与已经合入的版本。
2. 每个主要迭代使用一个 `feat/vX.Y-description` 分支；修改代码、对应 docs 和 MAIN 的版本链接。
3. 执行本地契约测试、notebook 校验及相关真实实验。
4. 自动 commit、push，创建含实际结果、限制与验证记录的 PR。
5. 在当前聊天中审查改动，并通过用户点名的 Code Review 插件读取 PR 检查。CI 检查不等同于独立人工/代理代码审查。
6. 用户确认阶段目标并在 MAIN 勾选后，将确认结果提交到对应 PR 并同步。未经确认不自行勾选或冒充验收完成；首版先保留 PR 供审阅。

每个 PR 的基本检查只有 CPU 单元测试与 notebook 格式校验，不在 CI 下载数据或占用 GPU 训练。训练报告由实际 notebook/脚本产生，记录具体环境与数据哈希。

不提交 `refs/`、数据集、权重、临时文件、运行时 URL/token。需要交付模型时在本地 artifacts 保存并明确对应版本；后续可单独决定发布附件。

这个流程由当前任务迭代执行，没有擅自安装后台定时推送任务。用户更新 MAIN 后在聊天里告知即可触发下一次同步。
